-------------------------------------------------------------------------------
3.1 · ⚠⚠⚠ LA API TIENE QUE SABER EXPRESAR **DOS FORMAS** DE DRENAJE, Y ESO SE
       DECIDE EL PRIMER DIA
-------------------------------------------------------------------------------
Esta es la unica cosa de este prompt que, si se escribe mal, **no se arregla
agregando codigo despues: se arregla rehaciendo B1**.

Las manifestaciones de §22 drenan **plano, una vez, cuando el evento ocurre**:

    standing 5%   ·   mist / singing / appear 10%   ·   chase 15%

Pero el **Phantom** ( §22.10, cerrado el 2026-08-20 ) drena **0,5% POR SEGUNDO
mientras el jugador lo mire, dentro de 10 m = 525 u**, y eso **SUMA al drenaje
base**: mirar un `singing` entero de un Phantom cuesta **10% + 7,5% = 17,5%**.

O sea que hay dos naturalezas:

    PLANO       un numero, una vez, con un motivo         ( eventos, manifestaciones )
    CONTINUO    una tasa por segundo, condicionada a algo  ( presencia, oscuridad, Phantom )
                que cambia tick a tick

⚠ La **presencia** de §19.8.2 ya es de la segunda familia, asi que las dos hacen
falta igual. Lo que hay que no hacer es escribir la primera y asumir que la
segunda "se agrega despues": el rasgo del Phantom **no entraria**, y el
instrumento no lo diria.

-------------------------------------------------------------------------------

bajo**. El reporte imprime, POR JUGADOR:

de tres estados -- tres significados para el mismo digito en la misma pantalla es
como se pierde una corrida.
